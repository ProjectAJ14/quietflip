# Quietflip: `packages/localization`

Type-safe user-facing strings (layer 0), generated by i69n from
`lib/messages.i69n.yaml` (English) and one `lib/messages_<code>.i69n.yaml` per
other language, plus the global `strings` accessor. It owns copy and locale
selection only: no widgets, no formatting helpers, no dependency on any
workspace package.

Languages: English (base and fallback), Spanish `es`, Portuguese (Brazil)
`pt`, French `fr`, German `de`, Italian `it`, Japanese `ja`, Korean `ko`,
Chinese (Simplified) `zh`, Hindi `hi`, Indonesian `id`, Turkish `tr`, Russian
`ru`. The translations are machine-made first drafts; each needs a
native-speaker review before release. Arabic (right to left) is not shipped.

Read the root `CLAUDE.md` and `packages/CLAUDE.md` first.

## Public API

Exported from `package:localization/localization.dart`.

| Symbol | Kind | Notes |
|---|---|---|
| `strings` | global getter | `LocalizationProvider.messages`, so the selected language; use `strings.<group>.<key>` |
| `Messages` | generated | Groups: `app`, `generic`, `common` (only `week`, `month`), `auth`, `profile`, `nav` (incl. `explore`), `notifications`, `errors`, `validation`, `developer` (`no_viewer`), `files` (design_system `FileInfoDialog`: field labels, `copied(field)`, `image_type(format)`), `clock` (flip_clock feature: modes, controls, settings, the sound picker (`tick_*` / `alarm_*` name and `_mood` per sound, group headers and hints), notification text, seconds button and hint, semantics `current_time(time)` / `time_remaining(time)` / `elapsed(time)`, `percent(value)`) |
| `<Group>Messages` | generated | e.g. `ErrorsMessages`, `ValidationMessages`; parameterised keys are methods (`errors.format_exception_message(code, postfix)`, `validation.invalid_key_config(of, key)`). Each language is a subclass, `Messages_<code>` |
| `LocalizationProvider` | static helper | `select(List<Locale>)` (the app calls it with the device languages at launch and on change; sets `currentLocale` and `Intl.defaultLocale`), `messages`, `currentLocale` (`'en'` until selected), `supportedLocales` (codes, English first), `locales` (as `Locale`s for `MaterialApp`), `isLocaleSupported`, `getBestMatchingLocale(List<Locale>)` |

## Layout

| Path | Responsibility |
|---|---|
| `lib/messages.i69n.yaml` | Source of every string, grouped by area |
| `lib/messages_<code>.i69n.yaml` | One per other language: the same keys and placeholders as English, values translated |
| `lib/messages*.i69n.dart` | Generated from the YAML. Never edit |
| `lib/src/localization_provider.dart` | Locale selection: the generated class per code, best match, fallback |
| `lib/src/strings.dart` | Global `strings` getter |
| `lib/localization.dart` | Barrel |
| `build.yaml` | i69n builder options: `default_locale: en`, `locales` (every code), `generate_for: lib/messages.i69n.yaml, lib/messages_*.i69n.yaml` |

## Rules

- Keys are snake_case and live under an existing group (`generic`, `errors`, `validation`, ...). A new top-level group becomes a new `<Group>Messages` class and getter on `Messages`.
- Parameterised messages use i69n's signature-as-key form in YAML: `name(String a, String b): "... $a ..."`.
- Matching is by language: the first device language Quietflip speaks wins (`pt_BR` and `pt_PT` -> `pt`), else English. Traditional Chinese (`zh_Hant`, or `zh` in TW/HK/MO with no script) is skipped, since only Simplified ships.
- Every new English key needs a value in every `messages_<code>.i69n.yaml`, with the same placeholders. `test/translations_test.dart` fails otherwise (a missing key would silently show English).
- No `_plural` in translations: i69n only knows English, Czech and Ukrainian plural rules. Phrase counted text so one form fits every number (`$n min`).
- User-facing text never appears as a literal in any `lib/`: `test/no_literals_test.dart` scans every app, feature, package and plugin for literals passed to `Text(` or to `label:`, `title:`, `message:`, `tooltip:`, `semanticsLabel:` and similar. An exception goes in its `_allowed` map with the reason.
- `core` reads `strings.errors.user_not_found` for `UserNotFoundException`; renaming a key breaks callers across the workspace. Grep before renaming or deleting.

## Common changes

- **Add a string:** add the key to the right group in `lib/messages.i69n.yaml` and its translation to every `lib/messages_<code>.i69n.yaml`, run `dart run melos run generate:i69n` (build_runner + `dart format lib/messages.i69n.dart`), then use `strings.<group>.<key>`. Commit the YAML and the regenerated `.i69n.dart` files together.
- **Add a parameterised string:** `key(String x): "text $x"` in the YAML, regenerate, call `strings.<group>.key(x)`.
- **Add a locale:** add `lib/messages_<code>.i69n.yaml`, list the code under `locales` in `build.yaml`, regenerate, then add its generated class to `_messages` in `LocalizationProvider`; extend `test/localization_test.dart`, add the code (Apple's form, e.g. `zh-Hans`) to `CFBundleLocalizations` in both `apps/quietflip/*/Runner/Info.plist` (the app's `bundle_localizations_test.dart` checks it) and check the layout in that language. A right-to-left language also needs a layout pass first.

## Tests

`test/localization_test.dart` covers matching (order, region fallback, Traditional Chinese skipped, unsupported and empty lists), `select` (strings and `Intl.defaultLocale`), the language list and that each language has its own copy. `test/translations_test.dart` checks every translation file against English (keys, placeholders, no empty text). `test/no_literals_test.dart` is the workspace-wide literal scan. Generated `*.i69n.dart` is excluded from the coverage gate (`tool/coverage.dart`), so new keys need no tests; new logic in `lib/src/` does.

Run: `dart run melos exec --scope=localization -- flutter test`. `dart run melos run coverage` must stay 100%.

## Gotchas

- `messages*.i69n.dart` are generated (`// GENERATED FILE, do not edit!`) and is skipped by both `tool/check.dart` and `tool/coverage.dart`. Never hand-edit it; `.claude/hooks/guard_generated.sh` blocks the edit.
- Shared button/state copy (`ok`, `cancel`, `save`, `try_again`, ...) lives in `generic`; `common` holds only `week` and `month`. Do not re-add duplicates to `common`.
- `select` changes global state (`strings`, `Intl.defaultLocale`). Tests that select a language reset with `LocalizationProvider.select(const [])` in `tearDown`.
- `Intl.defaultLocale` needs that language's date symbols before `DateFormat` without a locale runs; `GlobalMaterialLocalizations` (wired in the app) loads them.
